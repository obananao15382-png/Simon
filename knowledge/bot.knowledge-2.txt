# explain:
LUNGE_RANGE_START = 100 sets the minimum distance at which its lunge behavior can begin, while LUNGE_RANGE_STOP = 105 sets the distance where that lunge behavior ends. LUNGE_SPEED = 13.5 determines how fast it moves during the lunge. hasPath = 1 enables path-based movement, PATH_MIN_SPEED = 0.01 sets the minimum speed while following the path, and PATH = 8 tells it to use path number 8. PATH_THRUST_SPEED = 5 controls the speed of its path thrusts, PATH_THRUST_PHASE = 0.98 controls the timing/phase of those thrusts, and PATH_THRUSTS = 2 makes it perform two thrusts. BASE_VALUE = 450 gives the fish a base catch value of 450, and XP_VALUE = 150 gives 150 XP when caught. RESPAWN_DELAY = 210000 controls how long it waits before respawning. clumsiness_coefficient = 0.1 controls how much imperfect/clumsy movement it has, with 0.1 being fairly low. stayOutAtNight = 1 enables its behavior of staying out at night.

4. Make the segment physically follow the previous segment

Rotation alone isn't enough. You also need the segment's position to follow the previous segment.

For example, if your sprites are 40 pixels apart:

var distance = 40;

x = body.x - lengthdir_x(distance, body.image_angle);
y = body.y - lengthdir_y(distance, body.image_angle);

So the segment sits behind the previous segment.

A complete Step could therefore be:

if (instance_exists(body))
{
    var distance = 40;

    x = body.x - lengthdir_x(distance, body.image_angle);
    y = body.y - lengthdir_y(distance, body.image_angle);

    image_angle_offset += angle_difference(
        body_angle_last,
        body.image_angle
    );

    image_angle_offset = clamp(
        image_angle_offset,
        -image_angle_offset_max,
        image_angle_offset_max
    );

    image_angle = body.image_angle + image_angle_offset;

    body_angle_last = body.image_angle;

    image_angle_offset *= 0.9;
}
else
{
    instance_destroy();
}

1. Main Problematicus movement

The Other_10 code contains:

hspeed += ((target_x - x) * 0.02);
vspeed += ((target_y - y) * 0.02);
speed *= 0.98;

This means Problematicus doesn't instantly move toward its target.

Instead:

target_x - x determines horizontal acceleration.

target_y - y determines vertical acceleration.

0.02 controls how strongly it accelerates toward the target.

speed *= 0.98 applies a small amount of damping.


So its movement has an inertial/swimming behavior rather than directly setting its position.


---

2. Random target selection

Every frame it checks:

if (random(1) < (1/120))

If successful, it chooses a new target.

That's approximately a 1/120 chance per frame.

At 60 FPS, that averages roughly once every 2 seconds, although it's random rather than exactly every 2 seconds.

It creates:

var y_offset = 100;

Then:

target_x = (start_x - 1000) + (4 * lengthdir_x(1000, random(360)));

and:

target_y = 1294 + y_offset + 2000 + lengthdir_y(1000, random(360));

The important functions here are:

lengthdir_x()
lengthdir_y()

These generate an offset based on a random angle.

So the target isn't simply chosen randomly anywhere on the map; it is generated around a particular region using directional coordinates.


---

3. Vertical target limits

The code then constrains target_y.

Upper boundary:

if (target_y > (y_offset + 3400))
    target_y = y_offset + 3400 + ((y_offset + 3400) - target_y);

Lower boundary:

if (target_y < (y_offset + 2000))
    target_y = y_offset + 2000 + ((y_offset + 2000) - target_y);

This effectively reflects the target back into the allowed vertical region rather than simply clamping it.

With:

y_offset = 100;

the important boundaries become:

2000 + 100 = 2100
3400 + 100 = 3500

So the generated target is kept within approximately the 2100â€“3500 Y region through reflection.


---

4. Speed limits

After movement calculations:

if (speed < 15)
    speed = 15;

and:

if (speed > 30)
    speed = 30;

Therefore Problematicus has:

Minimum speed: 15
Maximum speed: 30

This is important because even though the acceleration/damping calculations might reduce its velocity, the game prevents the resulting speed from going below 15.

if (Worm_state == 3)

So when:

Worm_state == 3

it triggers:

fish_Jumpe();

This appears to be the special jumping behavior.

10. Tail smoothing

This line is particularly important:

image_angle_offset *= 0.9;

Every Step, the rotational offset is multiplied by 0.9.

That means it gradually decays toward zero.

This produces a smooth/spring-like trailing animation.

In simple terms:

This is likely responsible for the organic movement of the tail.

How to add new boats?

1. look on "BoatMenu_Create_0" and set the card_width to 5 so we can get an extra slot for our boat
2. export the sprites and take the sprites from these folders: spr_boat_7 and spr_boat_icon7 and then just paint all of them in a new color
3. import the new sprites but remember to change the '7' to '8'
4. create a new object called Boat8 and assign the spr_boat_8 to him.
5. look at the object Boat8 and the sprite of the icon 8 and save their id,will be useful later
6. look in boatdata_create_0 and add these things:
in the unlock part add unlocked[8] = -1;
at the cost part add cost[8] = (yourboatcost)
and before nItems add:
name[8] = "yourboatname";
object[8] = the id that u got on the boat8 object;
disp[8] = the id that u got on the icon boat sprite;
desc[8] = "description of your boat ";
7. go to your boat object and assign the Boat parent to it.
7.5 change all of your boat data step to:
for (i = 1; i < 6; i++)
{
    if (unlocked[i - 1] > 0)
        unlocked[i] = max(0, unlocked[i]);
}

if (CatalogData.count[3, 9] > 0 && CatalogData.count[0, 41] > 0)
{
    if (unlocked[7] < 0)
    {
        instance_create(0, 0, Message_TechBoat);
        unlocked[7] = 0;
    }
}

if (unlocked[7] > 0)
    unlocked[8] = max(0, unlocked[8]);
8. go to your boat object and add an create code, just copy everything from the boat 7 create code and change the setting whatever you like it,just remember to change boat_index to 8
9. temporary run your game and test it out
10. if you forgot assign the origin of the sprites so it doesn't glitch.
